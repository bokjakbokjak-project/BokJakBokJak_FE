# 질문 및 결정 관리

개발 중 확인이 필요한 기획·디자인·백엔드 계약을 기록하고, 상황형 설문 화면(`QuestionPage.tsx`, `QuestionProfilePage.tsx`)을 함께 두는 폴더다.

- [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md): 질문 목록과 결정 상태.
- [TEMPLATE.md](TEMPLATE.md): 상세 질문 작성 양식.

## 사용 방법

1. 기존 목록에서 같은 질문이 있는지 확인한다.
2. 영역별 ID를 부여한다: `BE`(백엔드), `PL`(기획), `DE`(디자인), `DEV`(개발 환경). 기존 코드의 참조 ID를 우선 확인하고 기존 ID는 변경하거나 재사용하지 않는다.
3. 현재 동작과 근거 파일, 확인할 질문, 답변 전 처리 방식을 적는다.
4. 긴 질문은 양식을 복사해 `BE-6-topic.md`처럼 별도 파일을 만들고 목록에서 링크한다.
5. 상태는 `미확인`, `확인 중`, `결정됨`, `반영 완료`, `보류` 중 하나를 사용한다. 답변 근거 없이 결정 상태로 바꾸지 않는다.
6. 답변 후 결정 내용과 근거 링크·날짜를 남기고 구현 및 문서 반영까지 추적한다.

초기 질문은 현재 코드에서 확인한 미연결·임시 동작을 기준으로 작성했다. 팀이 확정한 요구사항이나 담당자 배정을 뜻하지 않는다.
