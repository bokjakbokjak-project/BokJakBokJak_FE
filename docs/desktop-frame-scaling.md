# 데스크톱 화면 비율 설정

768px 이상 화면에서 앱을 어떻게 표시하는지 정리한 문서입니다. 레이아웃을 수정하거나 새 화면, 오버레이를 추가할 때 참고합니다.

## 요약

- **768px 미만(휴대폰):** 실제 화면 크기를 그대로 쓰고, 페이지 전체가 스크롤됩니다. 이번 변경으로 달라진 동작은 없고, 스크롤바만 보이지 않습니다.
- **768px 이상(데스크톱):** 390×844 프레임을 가운데 두고, 창 크기에 맞춰 글자와 이미지까지 통째로 확대/축소합니다.
- 데스크톱에서는 페이지 스크롤이 없습니다. 내용이 긴 화면은 프레임 안에서 스크롤합니다.

## 바꾼 이유

기존에는 데스크톱에서 프레임을 390px 넓이, 최대 844px 높이로 고정했습니다. 깨지지 않는 안전한 설정이었지만 두 가지가 아쉬웠습니다.

- 큰 모니터에서 앱이 작게 보이고 주변 여백이 큽니다.
- 노트북처럼 높이가 낮은 창에서는 넓이가 390px으로 고정된 채 높이만 줄어 비율이 달라지고, 설문 화면에서 시트가 장면 이미지를 많이 가립니다.

프레임 크기만 키우면 화면들이 390px 기준이라 내용이 390px로 남고 양옆에 여백이 생깁니다. 그래서 프레임의 넓이와 높이만 바꾸지 않고 내용까지 같은 배율로 조절합니다.

## 변경 전후

| 항목        | 변경 전               | 변경 후               |
| ----------- | --------------------- | --------------------- |
| 프레임 비율 | 창 높이에 따라 달라짐 | 항상 390:844          |
| 프레임 높이 | 최대 844px            | 창 높이 전체          |
| 프레임 넓이 | 390px 고정            | 높이에 맞춰 자동 계산 |
| 내용 크기   | 원래 크기 고정        | 프레임과 같은 배율    |
| 스크롤      | 페이지 전체           | 프레임 안에서만       |
| 스크롤바    | 표시됨                | 숨김(스크롤은 동작)   |

## 배율 계산

배율은 프레임 전체가 창 안에 들어가는 가장 큰 값입니다.

```ts
scale = Math.min(창 넓이 / 390, 창 높이 / 844)
```

넓은 창에서는 높이가 배율을 결정합니다. 창이 프레임보다 좁아지는 드문 경우에만 넓이가 결정합니다.

| 창 크기   | 배율    | 프레임 크기 | 18px 글자 |
| --------- | ------- | ----------- | --------- |
| 1280×650  | 약 0.77 | 약 300×650  | 약 14px   |
| 1280×844  | 1       | 390×844     | 18px      |
| 1920×1080 | 약 1.28 | 약 499×1080 | 약 23px   |

배율에 상한과 하한은 없습니다.

## 구현 방식

### 관련 파일

| 파일                                            | 역할                                            |
| ----------------------------------------------- | ----------------------------------------------- |
| `src/components/MobileLayout/frameScale.ts`     | 프레임 크기 상수와 배율 계산                    |
| `src/components/MobileLayout/MobileLayout.tsx`  | 배율 변수 갱신, 프레임과 스크롤 영역 구성       |
| `src/components/onboarding/YearPickerSheet.tsx` | 프레임 밖에서 같은 크기와 배율 적용             |
| `src/styles/global.css`                         | `scrollbar-none` 유틸리티, 페이지 스크롤바 숨김 |

### 구조

`MobileLayout`은 세 겹으로 되어 있습니다.

```text
바깥 영역    화면 전체. 데스크톱에서 프레임을 가운데 배치하고 페이지 스크롤을 막음
└ 프레임     390×844에 zoom 적용. 넘치는 내용을 자르고 fixed 오버레이의 기준이 됨
  └ 스크롤 영역   프레임 높이를 넘는 내용을 스크롤
    └ 각 페이지
```

프레임 관련 클래스에는 모두 Tailwind의 `md:` 접두사가 붙어 있습니다. 그래서 768px 미만에서는 적용되지 않습니다.

### 핵심 동작

- **배율 전달:** `useFrameScale`이 창 크기가 바뀔 때마다 배율을 계산해 `<html>`의 `--frame-scale` CSS 변수에 넣습니다. 프레임 밖에 렌더링되는 시트도 같은 값을 읽을 수 있도록 루트에 둡니다.
- **확대/축소:** 프레임에 `md:[zoom:var(--frame-scale,1)]`을 적용합니다. `transform: scale`과 달리 `zoom`은 레이아웃 크기까지 바뀌어서, 가운데 정렬에 별도 보정이 필요 없습니다.
- **fixed 오버레이:** 프레임의 `md:[contain:layout]` 덕분에 프레임 안의 `position: fixed` 요소는 창이 아니라 프레임을 기준으로 배치됩니다. 스크롤해도 프레임에 붙어 있습니다.
- **스크롤바:** `scrollbar-none`은 막대만 숨깁니다. 페이지와 프레임 내부 스크롤은 그대로 동작합니다.

## 화면을 추가할 때

- **기준 크기:** Figma의 390×844 값을 그대로 쓰면 됩니다. 배율 대응 코드를 따로 넣을 필요가 없습니다.
- **긴 화면:** 페이지 최상단 요소에 `overflow-hidden`을 넣지 않습니다. `flex-1`인 요소가 프레임 높이로 줄어들어 내용이 잘리고 스크롤도 되지 않습니다. 내용이 프레임 안에 다 들어가는 화면이라면 괜찮습니다.
- **오버레이:** 일반적인 `fixed` 오버레이는 프레임 안에 렌더링하면 자동으로 프레임에 맞습니다.
- **포털:** `createPortal`로 `body`에 렌더링하면 프레임 밖이라 배율이 적용되지 않습니다. `YearPickerSheet`처럼 `md:h-[844px] md:w-[390px] md:[zoom:var(--frame-scale,1)]`을 직접 적용해야 합니다.
- **뷰포트 단위:** 프레임 안에서는 `vh`, `dvh`로 높이를 잡지 않습니다. 데스크톱의 기준은 창이 아니라 844px 프레임입니다.
- **스크롤 위치:** 데스크톱에서는 스크롤 영역이 페이지 이동 후에도 유지됩니다. 긴 화면끼리 이동할 때는 이전 스크롤 위치가 남을 수 있습니다.

## 검증 범위

| 창 크기   | 확인 내용                                                                                         |
| --------- | ------------------------------------------------------------------------------------------------- |
| 1920×1080 | 프레임 약 499×1080, 페이지 스크롤 없음, 긴 화면은 프레임 안에서 스크롤, 시트가 프레임 하단에 맞음 |
| 1280×650  | 프레임 약 300×650, 온보딩 화면 표시, 연도 선택 시트가 프레임 하단에 맞음                          |
| 390×844   | 배율 1, 버튼 위치 동일, 페이지 전체 스크롤                                                        |

배율 계산은 `frameScale.test.ts`에서 테스트합니다.

## 아직 확인하지 못한 것

- Chrome 계열 브라우저에서만 확인했습니다. Safari, Firefox, 실제 휴대폰과 태블릿에서는 확인하지 못했습니다.
- 태블릿은 768px 이상이면 데스크톱 방식이 적용됩니다.
- 창이 낮으면 글자도 함께 작아집니다. 하한이 필요한지는 시연 환경에서 확인한 뒤 결정합니다.
