# 사용자 테스트 버전

2026-11-17 요청(`복작복작_사용자테스트_Claude_구현요청.md`)을 구현한 프론트엔드 부분이다. 기본값은 꺼져 있고, 운영 배포(`https://bok-jak-bok-jak-fe.vercel.app`)에는 설정을 넣지 않는다.

## 켜는 방법

| 변수                            | 값                        | 설명                                                                    |
| ------------------------------- | ------------------------- | ----------------------------------------------------------------------- |
| `VITE_API_MODE`                 | `server`                  | 실제 Google 로그인과 서버를 쓴다. 없으면 사용자 테스트도 꺼진다         |
| `VITE_USER_TEST`                | `true`                    | 사용자 테스트 화면을 켠다                                               |
| `VITE_USER_TEST_COHORT`         | 예: `local-2026-11`       | 테스트 회차. 영문·숫자·`-`·`_` 40자 이내. 상태와 답변을 회차별로 나눈다 |
| `VITE_USER_TEST_GENDER`         | `FEMALE` 또는 `MALE`      | 공통 성별 (미확정)                                                      |
| `VITE_USER_TEST_BIRTH_YEAR`     | 예: `2005`                | 공통 출생연도 (미확정)                                                  |
| `VITE_USER_TEST_DEPARTMENT`     | 예: `사용자테스트`        | 공통 학과 (미확정)                                                      |
| `VITE_USER_TEST_STUDENT_NUMBER` | 예: `00000000`            | 공통 학번 (미확정, 서버의 형식·중복 규칙 확인 필요)                     |
| `VITE_USER_TEST_DORMITORY`      | 예: `사용자테스트 기숙사` | 공통 기숙사 이름. 없으면 첫 저장 때 2인실로 등록된다 (미확정)           |
| `VITE_USER_TEST_FEEDBACK_API`   | `on`                      | 피드백을 서버로 보낸다. 서버 API가 생기기 전에는 넣지 않는다            |

모두 브라우저에 공개되는 값이다. 비밀값을 넣지 않는다. 플래그는 화면 분기용일 뿐 권한이나 데이터 분리를 보장하지 않는다.

### 로컬 서버로 실행

운영 링크와 별개로 로컬에서 운영 빌드와 같은 방식으로 띄운다.

```bash
# .env.usertest.local 에 위 변수를 넣는다(.gitignore 대상)
npx vite build --mode usertest --outDir dist/usertest
npx vite preview --mode usertest --outDir dist/usertest --port 5173 --strictPort
```

백엔드 CORS와 Google 로그인 허용 출처가 `http://localhost:5173`만 등록되어 있어 포트는 5173이어야 한다. 다른 포트나 별도 도메인을 쓰려면 백엔드 CORS와 Google Cloud Console의 승인된 JavaScript 출처에 그 주소를 추가해야 한다.

## 동작

- 로그인: 기존 Google 로그인 그대로. 로그인 응답의 `user_id`로 참여자를 기록하고, 설문을 마치지 않은 사용자는 시작 화면(`/user-test`)으로 간다. 설문을 마친 사용자는 서버 안내대로 홈으로 간다.
- 시작 화면: 공통값 안내, 피드백 안내, `설문 진행하기` / `시간이 없어서 그냥 둘러볼게요`.
- 기본 정보: 학교·프로필·기숙사 단계를 건너뛰고 공통값과 익명 이름 `테스터{user_id 세 자리}`를 채운다. 기존 API가 기본 정보와 우선순위를 한 요청(`PUT /api/me/onboarding`)으로 저장하므로, 서버 등록은 사용자가 우선순위를 고르고 `완료하기`를 눌렀을 때 이뤄진다. 학교는 서버가 로그인 계정에서 정한다. 학교 계정 인증은 우회하지 않는다.
- 둘러보기: 우선순위·설문 화면의 `둘러보기로 넘어가기`, 또는 시작 화면에서 들어간다. 홈·룸메이트·상세·분석·채팅·알림이 기존 예시 데이터로 바뀌고 서버에 프로필·추천·매칭 요청을 보내지 않는다. 모든 서비스 화면 위에 `둘러보기 모드예요. 프로필과 매칭률은 예시입니다.`와 `직접 설문하고 매칭하기`를 보여준다. 매칭률 원의 `매칭률`은 `예시`로 바뀐다. 대화 요청은 보내지 않고 `체험용 동작이며 실제 신청은 전송되지 않아요.`를 띄운다.
- 상태: 참여자 ID는 세션과 함께 sessionStorage에, 모드·설문 완료 여부·문항 상태는 localStorage `bokjak-user-test:{회차}:{user_id}`에 둔다. 로그아웃하면 참여자가 지워지고, 계정마다 상태가 따로다.

## 피드백 문항이 뜨는 시점

| 문항               | 대기열에 넣는 시점                                                              | 묻는 화면                                                         |
| ------------------ | ------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `q1_discovery`     | `PUT /api/me/survey` 성공(설문 전체 저장). 우선순위 완료나 둘러보기 전환은 제외 | 바로 다음 화면인 설문 결과(프로필 카드), 홈                       |
| `q2_understanding` | 상세 프로필의 답변 영역(AI 요약·답변 카드)이 화면에 절반 이상 보였을 때         | 돌아온 매칭 분석, 룸메이트 목록, 홈, 채팅 목록                    |
| `q3_negotiation`   | 매칭 분석(두 사람 비교)이 내용과 함께 표시됐을 때                               | 그 뒤의 룸메이트 목록, 홈, 채팅 목록. 분석 화면에서는 묻지 않는다 |

한 화면 진입에 한 문항만 띄운다. 상세 → 분석으로 돌아오면 Q2만, 그 다음 목록으로 가면 Q3가 뜨므로 Q2와 Q3가 같은 클릭에서 연속으로 뜨지 않는다. 각 문항은 회차당 한 번이며, 노출 시점의 모드·데이터 출처·설문 상태·대상 ID를 저장한다. 바깥을 누르거나 Escape를 누르면 건너뛰기로 기록한다.

## 아직 백엔드가 필요한 것

[backend-contract.md](./backend-contract.md)를 백엔드에 전달한다. 그 전까지는:

- 피드백은 이 기기에만 남는다(`delivery: local`). **운영자 수집은 연동되지 않았다.**
- 테스트 그룹 격리, 공통 프로필 분리, 운영 프로필 보존은 서버 작업이며 프론트만으로는 보장되지 않는다. 지금 서버를 그대로 쓰면 테스트 계정과 공통 기숙사가 운영 DB에 생긴다.
